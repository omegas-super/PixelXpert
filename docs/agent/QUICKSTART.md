# Quickstart

Fifteen minutes from a fresh clone to a correct first change. If you only read
one file, read this one.

**Audience:** an agent or contributor with no prior context on this repo
**Prereqs:** none

---

## Summary

- One APK, two roles: an app, and an injection module loaded into other
  processes.
- Features are **mod packs** — annotated Kotlin classes that hook a specific
  target process.
- Settings are **preference keys** shared by string between the app and the
  hooked side. Typos fail silently.
- Build discovery is generated by a KSP processor; a pack that is not annotated
  correctly never runs.
- You cannot build on this machine without installing a JDK and the Android SDK.
  See [build-locally](../guides/build-locally.md).

## Step 1 — Know what you are looking at

```text
app/src/main/java/sh/siava/pixelxpert/
├── xposed/          <- code injected into other processes
│   ├── XPLauncher.kt        entry point, context, pack loading, hot reload
│   ├── XposedRuntime.kt     the only bridge to libxposed
│   ├── XposedGeneration.kt  one loaded copy's hooks/threads/cleanups
│   ├── XposedModPack.kt     base class for every feature
│   ├── XPrefs.kt            preferences as seen from the hooked side
│   ├── annotations/         target annotations (@SystemUIModPack, …)
│   ├── modpacks/            the features themselves
│   └── utils/reflection/    the hooking DSL
├── ui/              <- Compose screens and the preference renderer
├── data/            <- PrefStore, RemotePrefProvider
├── service/         <- root binder, QS tiles
└── Constants.kt     <- broadcast actions and package names
```

Read `docs/agent/REPO_MAP.md` for the annotated version.

## Step 3 — The three things that silently break

These account for the majority of wasted debugging time in this repo. Internalise
them before writing code.

**1. A pack with the wrong annotation never runs.**
`XPLauncher` only constructs packs whose target matches the current process. The
KSP processor emits the table at build time. If you add a class and forget
`@SystemUIModPack` (or annotate it with the wrong target), there is no error, no
log, no crash. The feature is simply absent.

Verify by reading the generated registry after a build:

```text
app/build/generated/ksp/<variant>/kotlin/sh/siava/pixelxpert/xposed/ModPacks.kt
```

**2. A preference key typo produces no compile error.**
The app writes `"my_feature_enabled"`; the pack reads `"myFeatureEnabled"`. Both
compile. `XPrefs` returns the default, forever. Always grep the key string on
both sides before concluding a hook is wrong.

**3. Directory location does not determine target.**
`modpacks/systemui/IconPacks.kt` is annotated `@SettingsModPack` and runs in
Settings. Read the annotation, not the folder.

## Step 4 — Read one real pack end to end

Pick a small one and follow it completely. This is the fastest way to absorb the
shape of the codebase.

```text
app/src/main/java/sh/siava/pixelxpert/xposed/modpacks/systemui/CaffeineTile.kt
app/src/main/java/sh/siava/pixelxpert/xposed/modpacks/android/ScreenRotation.kt
```

For each, answer:

- Which annotation, and therefore which process?
- Which preference keys does it read, and where are they declared?
- Which framework methods does it hook, and via what `ReflectedClass` call?
- What does it release in `onUnloaded`, if anything?

If you can answer all four for both files, you are oriented.

## Step 5 — Before you build

This checkout has **no JDK, no Android SDK, and no Gradle cache**. `./gradlew`
will fail immediately. Install the toolchain first:

- JDK 21
- Android SDK platform 37
- `ANDROID_HOME` set

Full instructions and the failure-mode table are in
[build-locally](../guides/build-locally.md).

You can still read, grep, and write code without the toolchain. You cannot verify
it.

## Failure modes

| Symptom | First thing to check |
| --- | --- |
| "Nothing happens" after adding a pack | Generated `ModPacks.kt` — is your class in it? |
| "Nothing happens" after adding a setting | Grep the key string on both sides |
| Pack logs but hooks do not fire | Target process may be different from what you assumed |
| `./gradlew` fails instantly | No JDK on PATH — see [build-locally](../guides/build-locally.md) |
| Build succeeds but APK does nothing on device | Module not enabled in LSPosed for that scope |
